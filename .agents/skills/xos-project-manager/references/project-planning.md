# Project Planning

## Project brief

Keep the brief decision-focused. State the problem, target users, outcome, constraints, assumptions, and the decision needed next. Separate goals from non-goals and make the MVP explicit. Do not turn a proposed solution into a requirement until its value is clear.

## Scope

Define the smallest release that delivers a complete user outcome. List in-scope behavior, exclusions, dependencies, and known edge cases. Use Must / Should / Could / Won't for this release when it helps resolve trade-offs. Any added scope should identify what moves, what it costs, or which existing item it replaces.

## Milestones

Name milestones by verifiable outcomes rather than activity. For each, record included work, dependencies, owner, and exit criteria. Order milestones to validate the riskiest assumptions and unblock dependent work early. Keep milestones small enough to review and re-plan from feedback.

## Estimation

Estimate only when the work is understood enough to do so. Use relative size or ranges when precision is not supported; state assumptions, unknowns, and confidence. Include integration, review, verification, and release work. Do not convert estimates into dates without capacity and dependency information.

## Prioritization

Protect security, privacy, data integrity, and launch blockers first. Then prioritize core user journeys, uncertainty reduction, and dependencies before polish. Make the reason and trade-off visible; revisit priority when evidence or constraints change.
